# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`eztaox` is a JAX/`tinygp`-based framework for modeling multi-band AGN light curves with Gaussian Processes. It is generated from the LINCC Frameworks Python Project Template (see `.copier-answers.yml`); template-managed files (pre-commit config, workflows, `.setup_dev.sh`) may be changed back by `copier` template updates. The pre-commit config has deliberate local changes to keep: no `python3.11` pin, and the unit-test hook runs on pre-push instead of on every commit, skipping the slow `test_simulator.py` and `test_fitter.py`.

JAX is `>=0.12.0` (unpinned above that) and `requires-python` is `>=3.12, <3.15`. Float64 is enabled globally in `eztaox/__init__.py` (`jax_enable_x64`).

## Commands

Use Poetry to manage packages; don't install or upgrade packages with bare `pip`. Runtime dependencies live in `[project].dependencies`. Every development and testing dependency lives in the single `dev` extra under `[project.optional-dependencies]`, which Poetry reads and CI installs with `pip install -e '.[dev]'`. Don't add `[tool.poetry.group.*]` tables: CI never sees them. ### Test-specific notes

- `tests/conftest.py` adds a `--jax_cache` pytest option that points JAX's persistent compilation cache at `./.jax_cache` by default. This directory is large and git-ignored; don't delete it casually, it saves a lot of recompile time.
- `test_data` fixture loads `tests/data/unit_test_lc.npz`, regenerated by `tests/data/generate_data.py`.
- `tests/eztaox/_test_laguerre.py` is intentionally prefixed with `_` so pytest skips it: the Laguerre kernel (`kernels/_laguerre.py`) is experimental and hidden.
- `test_simulator.py` (43 tests, several seconds each) takes most of the suite's run time; `test_fitter.py` (parameter recovery over simulated light curves, parallelized with `joblib`) is next.
- Correctness tests compare against `tinygp`'s dense (non-quasisep) kernels and against `eztao`/`celerite` reference implementations.

## Architecture

The package is small (~4k lines) but the pieces interlock around one convention: **a model stores a kernel *definition* (an unravel function), and every call rebuilds the kernel from a flat parameter vector.**

### Kernels (`src/eztaox/kernels/`)

- `quasisep.py` subclasses each `tinygp.kernels.quasisep` kernel (`Exp`, `Matern32/52`, `SHO`, `Celerite`, `Cosine`, `Sum`, `Product`, `Scale`) to add a `.power(f)` PSD method, and overrides `__add__`/`__mul__` so compositions stay in the `eztaox` `Quasisep` hierarchy. It adds new kernels: `Lorentzian` and `CARMA(p,q)` (companion-form state space; AR coefficients `alpha` ascending order with leading coefficient fixed to 1, MA coefficients `beta` absorb sigma; `CARMA.from_quads` builds from quadratic-factor roots). Helper functions `carma_roots`, `carma_quads2poly`, `carma_poly2quads`, `carma_acvf` live here too. `MultibandLowRank` is a `tinygp` `Wrapper` that scales the base kernel's observation model by a per-band `amplitudes` array — this is the default cross-band covariance.
- `direct.py` has O(N^3) dense counterparts (`MultibandLowRank`, experimental `MultibandFullRank`) for kernels that aren't quasiseparable.
- `transfer_function.py`: `TransferFunction` subclasses (Gaussian/Exponential, causal variants) and `ConvolvedKernel`, which convolves a quasisep base kernel with a transfer function via FFT of the PSD (hence the need for `.power`). It is a dense kernel, so models using it fall back to the direct path.
- `eqx_utils.find_param_by_name` walks an Equinox module pytree by attribute name (used by `ConvolvedKernel` to find `scale`).

Kernels are Equinox modules; `jax.flatten_util.ravel_pytree(kernel)` gives `(flat_params, unravel_fn)`. Models keep only `unravel_fn` as `base_kernel_def`.

### Models (`src/eztaox/models.py`)

`MultiVarModel` (Equinox module) is the fitting interface; `UniVarModel` is a thin single-band subclass that disables lags. Inputs are `X = (t, band_index)`. Construction sorts by time and precomputes per-band index arrays so that lag shifts can be re-sorted cheaply with `ts_utils.merge_sort` inside JIT (`_lag_transform_fast`) instead of a full argsort.

`_build_gp(params)` (filter-jitted) is the heart: it reads the params dict, applies amplitude scaling, lags, optional jitter, rebuilds the kernel via `base_kernel_def(jnp.exp(params["log_kernel_param"]))`, wraps it in the multiband kernel, and returns a `tinygp.GaussianProcess` plus the sort indices. `log_prob`, `aic`, `bic`, `sample` (numpyro), and `pred` all go through it. If the kernel is quasiseparable, `assume_sorted=True` is passed; dense kernels (`direct.*`, `ConvolvedKernel`) work through the same interface without it.

**Parameter dict convention** (keys the models look for): `log_kernel_param` (log of the flattened kernel params, required), `mean` (per-band, when `zero_mean=False`), `log_amp_scale` (bands 1..n-1; band 0 fixed at 0), `lag` (bands 1..n-1; band 0 fixed at 0, when `has_lag=True`), `log_jitter` (per-band, when `has_jitter=True`). Custom `mean_func`, `amp_scale_func`, `lag_func` callables can replace the defaults.

### Simulator (`src/eztaox/simulator.py`)

`MultiVarSim`/`UniVarSim` mirror the model classes (same kernel-def, multiband kernel, mean/amp/lag conventions) but generate light curves on a uniform grid from `min_dt`/`max_dt`. Methods: `full` (whole grid), `random` (random subsample), `fixed_input` (simulate the full grid, then pick nearest grid points to user-supplied times) and `fixed_input_fast` (build the GP directly at the user-supplied times and sample there). `ts_utils.add_noise` adds Gaussian observational noise afterwards.

### Fitting (`src/eztaox/fitter.py`)

Built on `optax`. `random_search` draws `n_sample` initial parameter sets from a numpyro-style `init_sampler` (uses `numpyro.sample` + `numpyro.handlers.seed`, vmapped over keys), evaluates the loss in batches with `jax.lax.map`, keeps `n_best`, and locally optimizes each. `simple_optimizer` runs one optimizer from a given start and returns full param/loss/grad histories. Both accept any `optax.GradientTransformation`; set `use_value_and_grad_from_state=True` for L-BFGS-style optimizers. `scripts/compare_fit_optimizers.py` compares optimizers end to end.

### Second-order statistics (`src/eztaox/kernel_stat2.py`)

`gpStat2` takes a kernel and exposes `acf`, `sf` (structure function), `psd` as functions of lag/frequency, rebuilding the kernel from its flat params so they can be evaluated at alternative parameter values.

## Conventions

- Ruff enforces Google-style docstrings on public classes/functions (`D10x` rules) and isort ordering; `N803/N806/N815` are disabled so scientific capitalized names (`X`, `N`, `simN`) are fine.
- Parameters that must be positive are stored in log space in the params dict (`log_kernel_param`, `log_amp_scale`, `log_jitter`); kernel constructors take linear-space values.
- Notebook outputs are cleared by pre-commit on commit, except those under `docs/pre_executed/`, which must never be executed by CI.
- Pre-commit blocks commits directly to `main`; work on a branch and open a PR against `main`. The PR template asks for a change description and a solution description.
- `Changelog.rst` is updated per release with PR links.

## Coding style

New code must read like the existing modules (`models.py`, `simulator.py`, `fitter.py`, `kernels/quasisep.py`). Match these habits, not just the linters:

- **Module layout.** One-line module docstring first (a short paragraph after it is fine). Imports in isort groups: stdlib, third party, then `from eztaox...`. Standard aliases: `import jax.numpy as jnp`, `import jax.random as jr` (tests/scripts), `import equinox as eqx`, `import tinygp.kernels as tk` / `tinygp.kernels.quasisep as tkq`, `from tinygp.helpers import JAXArray`, `from numpy.typing import NDArray`, `from collections.abc import Callable`. Kernel modules start with `from __future__ import annotations`.
- **Type hints everywhere on public signatures.** Array inputs are `JAXArray | NDArray`, parameter dicts are `dict[str, JAXArray]`, keys are `jax.random.PRNGKey`, callables are `Callable`; spell out tuple return types; `__init__` and test functions return `-> None`. Use `X | None`, not `Optional`.
- **Signatures.** Required positional args first, then a bare `*` and keyword-only options with defaults; boolean switches (`zero_mean`, `has_jitter`, `has_lag`) arrive via `**kwargs` and are read with `kwargs.get("name", default)`. Public functions use plain positional arguments where the notebooks call them positionally (`random_search(model, init_sampler, key, n_sample, n_best)`).
- **Docstrings** are Google style and ruff-enforced on public classes/functions. Pattern: one-line imperative summary, blank line, optional body, then `Args:` entries as `name (type, optional): Description. Defaults to X.` and a `Returns:` line that starts with the type. A class's constructor arguments are documented in the class docstring, not in `__init__`. Use `r"""` with `:math:` and `.. math::` for formulas, RST links like `` `Kelly et al. (2014) <https://arxiv.org/abs/1402.5978>`_ `` for references. Private `_helpers` get a short one-line docstring or none; use `# noqa: D102` plus `# TODO: Write docstring.` only when overriding a tinygp method with a self-explanatory name.
- **Comments** are short, lowercase section labels that split a function into steps (`# format inputs`, `# assign attributes`, `# build gp`, `# select top n_best`), each block separated by a blank line. Reserve full-sentence comment paragraphs for non-obvious numerical or performance decisions (see `CARMA._companion_transition` and the top of `benchmarks/fitting.py`), and say *why*, not what.
- **Naming.** snake_case for functions and most variables; scientific camelCase is accepted for arrays and counts (`bestP`, `simN`, `nRand`, `flatPost`, `nPair`); matrices may be capitalized (`X`, `F`, `V`). Classes are PascalCase (`gpStat2` is the one exception, marked `# noqa: N801`). Positive parameters live in log space with a `log_` prefix in the params dict; kernel constructors take linear values. Per-band arrays are indexed by band index with band 0 as reference.
- **JAX/Equinox idioms.** Models, simulators and kernels are `eqx.Module`s: declare fields as class annotations, assign them in an explicit `__init__`, mark non-array config with `eqx.field(static=True)`, decorate hot methods with `@eqx.filter_jit` and free functions with `@jax.jit` or `@partial(jax.jit, static_argnames=(...))`. Convert inputs at the boundary with `jnp.asarray` (band indices `dtype=int`), keep `jnp` (not `np`) inside library code, and batch with `jax.vmap`, `jax.lax.map`, `jax.tree_util.tree_map` instead of Python loops over data. Store kernel *definitions* (`ravel_pytree(kernel)[1]`) and rebuild from flat params. Branch on `isinstance(kernel, tk.quasisep.Quasisep)` to pass `assume_sorted=True`.
- **Errors** are `ValueError`s with an f-string that states the expected and actual value.
- **Tests** mirror the library style: module docstring, `random` fixture from `numpy.random.default_rng(<fixed seed>)`, a `data` fixture built from it, parametrized fixtures over a list of kernels, `pytest.param(..., id="adam")` for named cases. Correctness is asserted with `tinygp.test_utils.assert_allclose` against the dense tinygp kernel, `eztao`, or `celerite`; parameter-recovery tests assert on mean/MAD of the error over many fits. Section-label comments and `-> None` apply here too.
- **Scripts and benchmarks** use module-level UPPER_CASE constants, an `argparse` `parse_args()` and a `main()` guard, `functools.cache` for expensive shared setup.
- Run `ruff check --fix` and `black` (88 columns) before committing; don't add new `# noqa` or `# type: ignore` without a reason in the same line.

## Tutorial notebook style

New tutorials go in `docs/notebooks/` and must follow the existing ones (`01_DRW`, `03_MultibandFitting`, `04_MultibandSimulation`, `05_MultibandPrediction` are the reference set):

- **File and registration.** Name it `NN_CamelCaseTopic.ipynb` with the next two-digit number. Register it in three places: the `toctree` in `docs/notebooks.rst` (numbered entry `N. Title <notebooks/NN_Topic>`, keep the DP1/LSDB pre-executed notebook last), the tutorial list in `docs/index.rst` (`:doc:` link plus a one-sentence "Demonstrating ..." description), and the bullet list in `docs/notebooks/README.md`. Kernel is `python3`; outputs are cleared (pre-commit does it). CI executes every notebook here, so keep the runtime small: ~1e3-1e4 random-search samples, one MCMC chain with a few thousand draws. Anything heavy or needing external data goes to `docs/pre_executed/` with the `nbsphinx: execute: never` metadata.
- **Cell 0 is the standard setup cell**, copied verbatim from an existing notebook: matplotlib/numpy/warnings imports, `warnings.filterwarnings("ignore", category=RuntimeWarning)`, the `mpl.rcParams.update({...})` block (`text.usetex: False`, label/tick sizes, constrained-layout padding zeroed, `axes.linewidth`, `figure.figsize: (9, 6)`, `legend.fontsize: 15`, `legend.frameon: False`), then `import jax`, `import jax.numpy as jnp` and `jax.config.update("jax_enable_x64", True)` under the comment `# you should always set this`.
- **Cell 1 is the title cell**: an `###` heading with the tutorial name, then one or two paragraphs saying what the notebook demonstrates and why, with **EzTaoX** in bold, class and function names in backticks, links to related tutorials as `[Multiband Fitting](03_MultibandFitting.ipynb)`, the model's kernel written out in a `$$ ... $$` display equation with the symbols defined in prose. Use `<div class="alert alert-info">**Note** ... </div>` for conventions (parameter notation, literature parameterization). Longer notebooks end the intro with a numbered "We will:" list.
- **Sections** are `#### 1. Title`, subsections `##### 1.1 Title` (no `#`/`##` headings; the title is the only `###`). Each heading cell carries one to three sentences that explain the step and name the API it uses. The canonical order is: Light Curve Simulation, Light Curve Formatting (`formatlc`, multiband only), Light Curve Fitting (Initialize model, Define Init Sampler, MLE Fitting), MCMC (Define `numpyro` model, Run, Visualize chains/posteriors), Second-order Statistics (SF, PSD), then any topic-specific sections and a closing interpretation paragraph.
- **Imports from `eztaox`** (and `numpyro`, `arviz`) go in a small code cell at the start of the section that first uses them, not all in cell 0.
- **Code cells are short, one step each.** Set named parameters at the top of the cell (`drw_scale, drw_sigma = 100.0, 0.15`, `min_dt, max_dt = 1, 3650.0`, `n_sample = 10_000`, `n_best = 10`), use explicit `jax.random.PRNGKey(n)` seeds (name them `lc_seed`, `noise_seed`, `fit_key`, `mcmc_seed` when several), add lowercase `#` comments as step labels, prefix fitting and MCMC cells with `%%time`, and end a cell with a bare expression (`m`, `bestP`, `X, y, yerr`) when showing the object is the point. Print true vs fitted values side by side (`"True DRW Params (in natural log):"` style). Say in a comment that the kernel's init values are not used by the fit.
- **Explain the parameter conventions every time** they appear: a "Model parameters" bullet list with bold names (`log_kernel_param`, `log_amp_scale`, `mean`, `lag`), band 0 as reference band, `M-1` entries for per-band arrays, log-space for positive parameters. The `init_sampler` always uses `numpyro.sample` per parameter and `numpyro.deterministic("log_kernel_param", ...)`, and the MCMC model reuses it (`sample_params = init_sampler(); m.sample(sample_params)`).
- **Plots** follow `05_MultibandPrediction` and rely on the cell-0 defaults: don't pass `figsize` to a single-panel plot, since the 9x6-inch default renders at the full width of the docs column (a custom size is only for multi-panel or `arviz` figures). Put the legend in one row above the axes with `plt.legend(ncol=N, loc="lower center", bbox_to_anchor=(0.5, 1.0))`. Light curves are labeled `"Time (day)"` and `"Flux (mag)"` with the magnitude axis inverted (`plt.gca().invert_yaxis()`), data are error bars with `fmt="."` colored by band from a `band_colors` dict (`g` green, `r` red, `i` orange, as `tab:` colors), and a noise-free truth is a thin semi-transparent gray line drawn behind the data.
- **Voice**: first-person plural, didactic and concrete ("We first simulate...", "Here, we demonstrate how to use..."), aimed at AGN astronomers new to GPs; explain what a result shows right after the plot or printout, and close with an interpretation markdown cell when the notebook makes a comparison.
